# Course rules, 259.075

These apply to all seven sessions.

## No excuses, in either direction

There is one sentence nobody should be able to say: "My code didn't run, so I handed in nothing."
The course is built against it, and built so that it doesn't become a convenient way out either.

**In class.** Every gap you fill in has a solution, and it is released after ten minutes, not at
the end. If you are stuck, take it, read it and carry on. It costs no points, because the points
are elsewhere. Once you have it, you keep working on the same task as everyone else, just with
someone else's code as your starting point.

**In the homework.** After the session, the code is in the solution notebook. Code is therefore
never the reason for a missing submission. What you hand in is your own run, with your own
numbers and your own interpretation of them. If you used lines from the solution, say so in one
line at the top of your text. That is no disgrace and costs nothing.

**What does count.** No submission means zero points, and the interpretation is graded strictly.
If you write what you saw and explain what it means, you get the points, borrowed code or not. If
you write five general sentences that would fit any model, you don't.

**If you are not running after ten minutes**, pair up with someone at their machine. Don't watch;
take notes.

## Why

This course tests whether you can judge a model, not whether you can type Python. Programming is
a tool, and a tool can be handed to you. Judgement can't.
